// how it works

      
Pasting logs costs you before any tool can help.

      
Claude reads everything you send it. So комп never takes logs through the chat: it reads them itself, on your laptop, and hands Claude only the summary.

      

        
Copy the logs
From kubectl, Docker, Grafana, CI output, anywhere. Just Cmd+C.

        
Ask Claude
“What's wrong in the logs I copied?” No pasting, so no thousands of tokens up front.

        
Claude reads the summary
Claude calls compress_clipboard. комп reads your clipboard locally and returns a few hundred tokens.

      

      

        
~76,000
tokens to paste the 2,001-line Go outage log into the chat. Your context fills up and long sessions hit limits sooner.

        
~312
tokens for the комп summary of the same log. Claude still found the outage, the retries and the 503s.

      

    


    

      
// what it keeps

      
Shorter, without losing the plot.

      
комп is lossy on purpose: it drops repetition, not meaning. These rules decide what stays.

      

        
Errors keep their details
Warnings and errors list their actual values and keep their stack traces.
ERROR query failed err="dial tcp 10.0.3.17:5432: connection refused" ×200

        
Bursts get their own line
A value seen only during one stretch is split out with its own time range.
10:04:06–10:06:49 GET /api/orders/… status=503 ×100

        
Stack traces, folded
Printed once per group. Runs of framework frames collapse into one line.
at ShippingService.quote(ShippingService.java:57)
… 12 framework frames

        
Order survives
Every entry carries its first and last timestamp, so cause and effect stay visible.
10:00:01–10:00:07 INFO GET /health 200 1–3ms ×4

        
Shared fields, said once
A pod name or service=orders on every line moves into the header.
[komp] 2001 lines → 9 entries · service=orders

        
Nothing silently dropped
If there are too many patterns, the rarest low-severity ones go, and the output says so.
… 120 rarer low-severity patterns omitted (450 lines)

// mcp tools

      
Three tools Claude can call.

      
комп speaks the Model Context Protocol over stdio. Claude Code starts it in the background; it needs no network and no account.

      

        
Tool
Arguments
Reads logs from

        
compress_clipboard
max_entries?
whatever you copied

        
compress_file
path, max_entries?
a log file on your machine

        
compress_kubectl_logs
pod, namespace?, container?, since?, tail?, previous?
kubectl logs --timestamps with your current kube context

      

    


    

      
// install

      
Two commands.

      
Install the binary, then connect it to Claude Code. It also works as a plain terminal command.

      

        

          
1 Install комп

          

            
            
            
          

          

            
curl -fsSL https://raw.githubusercontent.com/samchinmaya/komp/master/install.sh | sh

            
Downloads the right binary, checks its SHA-256 and installs to ~/.local/bin.

          

          

            
Download komp-x86_64-pc-windows-msvc.zip from the latest release and put komp.exe on your PATH.

          

          

            
cargo install --git https://github.com/samchinmaya/komp

          

        

        

          
2 Connect to Claude Code

          
claude mcp add --scope user komp -- komp serve

          
For a whole team, commit this as .mcp.json in your repo:

          
{ "mcpServers": { "komp": { "command": "komp", "args": ["serve"] } } }

        

      

      

        
Use it from the terminal too

        
komp                       # compress the clipboard
komp app.log               # compress a file
kubectl logs api | komp -  # compress stdin

// faq

      
Questions.

      

        
Does комп send my logs anywhere?
No. It's a local program. It reads your clipboard, a file or kubectl on your machine and returns text to Claude Code over stdin/stdout. It makes no network requests.

        
Why not just paste the logs into Claude?
Everything you paste is read, and billed, in full before any tool runs. A 2,000-line log is tens of thousands of tokens. With комп the raw logs never enter the conversation; only the summary does.

        
Doesn't compression lose information?
It removes repetition, not meaning. Identical lines merge with a count, varying values become ranges or short lists, and errors and warnings keep their values and stack traces. When something is dropped for space, the output says how much.

        
Does it work without Claude?
Yes. komp is a normal command-line tool: run it on a file, on stdin or on your clipboard and read the summary yourself.

        
Which log formats does it understand?
Plain text with timestamps and levels, JSON lines (including pino's numeric levels), logfmt, klog (kubelet, apiserver), syslog, Spring Boot, Java stack traces and Python tracebacks. Unknown formats still get deduplicated and templated.

        
Is it free?
Yes, MIT licensed and open source on GitHub.
